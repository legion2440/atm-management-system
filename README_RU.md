# ATM Management System

Терминальная система управления банковскими счетами на C. Реализован весь обязательный scope задания 01-edu: регистрация и вход, создание и управление счетами, расчёт процентов, транзакции, удаление счетов и передача владельца.

Проект сохраняет совместимое с заданием текстовое хранилище, хранит пароли как SHA-256 хэши и в качестве бонуса умеет мгновенно уведомлять пользователя о переданном ему счёте между двумя активными POSIX-терминалами.

## 🚀 Быстрый запуск

### Требования

- GCC или Clang с поддержкой C11
- GNU Make
- Bash для тестовых скриптов
- Linux / WSL рекомендуется для POSIX-бонуса с уведомлениями

### Клонирование

```bash
git clone https://01.tomorrow-school.ai/git/nyestaye/atm-management-system
cd atm-management-system
```

### Сборка

```bash
make
```

### Запуск

```bash
./atm
```

На нативной Windows с MinGW/Git Bash бинарник может называться `atm.exe`.

В репозитории изначально есть два тестовых пользователя:

| Пользователь | Пароль |
| --- | --- |
| `Alice` | `1234password` |
| `Michel` | `password1234` |

Пароли в `users.txt` лежат не открытым текстом, а как SHA-256 хэши.

Вернуть исходные тестовые данные после ручных проверок:

```bash
bash scripts/reset_data.sh
```

## 📝 О проекте

Приложение следует исходному заданию ATM Management System и использует простой терминальный интерфейс. После входа пользователь работает только со своими счетами. Любое изменение сразу сохраняется в файлы данных.

Меню авторизованного пользователя:

1. Создать новый счёт
2. Обновить данные счёта
3. Посмотреть один счёт и проценты
4. Посмотреть список своих счетов
5. Выполнить транзакцию
6. Удалить счёт
7. Передать владельца
8. Выйти из аккаунта

Номера счетов глобально уникальны. Поля country и phone хранятся одним токеном без пробелов, так как исходный формат задания разделяет поля пробелами.

## ✨ Возможности

### Аутентификация

- регистрация новых пользователей;
- запрет одинаковых имён;
- вход по сохранённым данным;
- хранение паролей в SHA-256;
- возможность прочитать legacy-строки со старым plaintext-паролем, если такие данные импортированы.

### Управление счетами

- типы `current`, `saving` / `savings`, `fixed01`, `fixed02`, `fixed03`;
- изменение только телефона или страны, как требует задание;
- просмотр одного своего счёта;
- список всех своих счетов;
- запрет доступа к чужому счёту;
- удаление существующего счёта;
- передача счёта другому зарегистрированному пользователю.

### Транзакции

- пополнение `current` и `savings`;
- снятие с `current` и `savings`;
- запрет нулевой и отрицательной суммы;
- запрет снятия больше доступного баланса;
- полный запрет транзакций для `fixed01`, `fixed02`, `fixed03`;
- немедленное сохранение нового баланса.

## 💰 Правила процентов

Расчёт соответствует контрольным значениям официального audit-листа.

| Тип | Правило | Пример audit для `$1001.20`, дата `10/10/2012` |
| --- | --- | --- |
| `current` | без процентов | сообщение об отсутствии процентов |
| `savings` | 7% годовых, выплата ежемесячно | `$5.84` каждого месяца, 10 числа |
| `fixed01` | 4% × 1 год | `$40.05` на `10/10/2013` |
| `fixed02` | 5% × 2 года | `$100.12` на `10/10/2014` |
| `fixed03` | 8% × 3 года | `$240.29` на `10/10/2015` |

Логика типов счетов, дат и процентов находится в `src/account.c`, поэтому CLI и тесты используют одни и те же правила.

## 💾 Хранение данных

Основная реализация использует текстовые файлы из задания:

```text
data/
├── users.txt
└── records.txt
```

`users.txt`:

```text
<id> <username> <password-hash>
```

`records.txt`:

```text
<id> <user_id> <owner> <account_number> <dd/mm/yyyy> <country> <phone> <balance> <type>
```

При изменении данные сначала записываются во временный файл, затем заменяют основной через `rename`.

Тесты задают `ATM_DATA_DIR` и работают с отдельной временной копией данных, поэтому `data/` проекта не портится.

## 🔔 Уведомления о передаче

На POSIX при входе создаётся FIFO конкретного пользователя в `/tmp` и дочерний процесс-слушатель. Если из другого активного терминала этому пользователю передать счёт, он сразу увидит:

```text
[NOTIFICATION] You received account 777 from Alice.
```

Так реализован бонус задания с мгновенным уведомлением без изменения обязательного формата хранилища.

На нативной Windows отключён только FIFO-бонус; сама передача счёта работает. Для проверки этого пункта audit используйте Linux/WSL.

## 🧪 Тесты и аудит

Полный локальный прогон:

```bash

```

Сборка выполняется с:


Далее проверяются:

- даты и все контрольные значения процентов;
- регистрация Marcus и запрет повторной Alice;

ASan + UBSan:



## ⚠️ Примечания

- Основной backend — исходное текстовое хранилище. SQLite не добавлялся, поэтому бонус за relational database не заявлен.
- SHA-256 здесь используется как учебный бонус защиты пароля. Для production нужен медленный salted KDF вроде Argon2, scrypt или bcrypt.
- FIFO-уведомления являются POSIX-специфичным бонусом. Остальная ATM-логика от них не зависит.
- Внешние C-библиотеки не требуются.
